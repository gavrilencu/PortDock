## Security fixes

This release closes several ways a project member could reach the server or other teams' data, found in a new security review. Updating is recommended for every installation.

### Security

- **Docker Compose files are checked as Docker Compose runs them.** The check now reads the output of `docker compose config`, with variables interpolated and `extends` and `include` merged, so `${VAR}`, other compose files and `.env` can no longer bring in privileged mode, host namespaces or server paths. Volumes and networks outside the project, local volume `driver_opts`, macvlan/ipvlan networks, build contexts, env files, secrets and build caches outside the repository, custom seccomp profiles, the Docker API socket, `traefik.*` labels and providers are refused unless an administrator allows host access. Paths that lead outside the repository through a symbolic link are refused, and so are paths inside another service's writable bind mount, where a container could swap them for a link.
- **Custom services (one-click and pasted compose) are checked like compose applications.** They were not checked before. Like applications, they can be given *Allow host access* by an administrator (service *Settings*).
- **Extra `docker run` options:** `--mount` is parsed the way Docker parses it, and its volume driver options are refused; members can no longer mount the volumes of other resources (databases, compose projects, managed volumes) by name.
- **Azure DevOps:** the clone URL now comes from the organization, never from the request, so the connection's token cannot be sent to another server.
- **Git credentials are removed from the checkout** right after the clone, submodules included, so a build cannot read the token from `.git/config`. The build context, Dockerfile, compose file and publish directory must stay inside the repository, symbolic links included.
- **Pull requests from forks are no longer deployed as previews** (GitHub, Gitea, GitLab, Azure DevOps): their code would run with the application's variables. Branches and commits received from webhooks and the deploy hook are validated.
- **Members can no longer change their own e-mail address**, which single sign-on and LDAP use to link a first sign-in to an account; administrators change it from *Team*, and their own with their current password.
- **Cross-site requests are refused:** a page on another site, including an application hosted on a sibling subdomain, can no longer use a signed-in user's session to change anything.
- Viewers no longer see a container's command, arguments and health check in *Inspect*, where database passwords appear.
- The sign-in page no longer follows `next` links that browsers turn into another site (`/<tab>/example.com`).
- Persistent volumes: a preview's volumes can no longer collide with a production volume named like `data-pr1`, and an existing volume is reused only if PortDock created it for that application.

### Fixes

- Members opening an organization tab of *Settings* by its link (Team, Notifications, Authentication…) see their profile instead of an error page; the *Team* link is shown to administrators only.
- Testing an LDAP directory with a user who belongs to no group no longer shows an error page.
- Docker images from the catalog keep their data in managed volumes (Storage tab) instead of volumes set in the docker options.

### Notes

- A compose file that uses something now refused fails at the next deploy with a message naming it; an administrator can allow host access for that application or service.
- Compose files that give a volume or network a fixed `name:` (outside the project) need host access now, since that name is shared with every other project on the server.
- A writable bind mount of the whole repository (`.:/app`) next to other files the project uses (an env file, another bind mount inside it) is refused: mount it read-only (`.:/app:ro`).
- Services whose compose file uses something now refused can be saved again once an administrator allows host access for them.
- In extra `docker run` options, members can no longer use volume names starting with `sy-` or `pd-`, which PortDock uses for its own volumes; options saved earlier keep working.
- Preview volumes created by v1.13.0 are removed when their pull request closes, as before.
