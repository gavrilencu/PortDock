## The application's port comes from its image

An application whose port did not match the one its container listens on (a Dockerfile serving nginx on port 80, with the default port 3000) failed on Kubernetes after several minutes, with only *CrashLoopBackOff* to go by. PortDock now takes the port from the image, and explains when it cannot.

### New

- **The port is taken from the image automatically.** At every deployment PortDock reads the ports the image declares with `EXPOSE`: an image built from Git right after its build, a prebuilt image from its registry (without pulling it). When the application's port is not one of them, PortDock switches the application to the image's port, saves it, and the domains, the health check and the `PORT` variable follow: *Port: the image listens on port 80 (EXPOSE 80), so the application's port is now 80 instead of 3000.* With several ports, the usual HTTP one is chosen (80, 8080, 3000…).
- **Applications that work are left alone.** The port changes by itself only until the application's first successful deployment, and never when you set a `PORT` variable yourself. After that, a mismatch is reported in the log instead: *The image declares port 80 (EXPOSE), but the application's port is 3000…*
- **New applications start with the right port.** A repository with a Dockerfile gets the port its final stage exposes when you create the application (`EXPOSE 80` → port 80), instead of 3000 every time.

### Fixes

- **On Kubernetes, a pod that never answers fails the deployment at once.** A container restarted before it ever passed its health check had its whole startup time already, so PortDock no longer waits through the back-off of every restart (about six minutes for five restarts). The deployment stops right after the first restart, keeps the previous version running, and explains the cause:
  - *Nothing answered on port 3000 within 60 s, and the image declares port 80 (EXPOSE): set the application's port to 80 in Configuration → Network*;
  - or, when the image declares nothing else, to check that the application listens on that port on all interfaces (0.0.0.0, not 127.0.0.1), or to give a slow application a longer health check timeout.
- A container that crashes says so with its exit code (*its container exits with code 1*) instead of only *CrashLoopBackOff*.

### Notes

- An application that never deployed successfully, like one stuck on the wrong port, gets the right port at its next deployment: just deploy again.
- An image that declares no port (no `EXPOSE`, as with Nixpacks) keeps the application's port; PortDock passes it to the application in the `PORT` variable.
- Update PortDock on Kubernetes by running the installer again, or with `kubectl -n portdock set image statefulset/portdock portdock=ghcr.io/gavrilencu/portdock:v1.17.1`.
