## Updates from the dashboard, in Kubernetes too

**Update available** now works for a PortDock that runs in Kubernetes, as it does on Docker: one click, and PortDock replaces itself with the new version, or comes back to the current one if the new one does not start.

### New

- **One-click updates in Kubernetes** (sidebar → **Update available**, or *Settings → Updates*, and the automatic night-time updates):
  1. PortDock checks that the new image is signed by the release workflow (Sigstore), and pins it to the verified digest.
  2. It backs up its database and encryption key, as on Docker.
  3. It starts a Job of its **current** image in its namespace. The Job points PortDock's StatefulSet at the new image and waits up to five minutes for its pod to be ready.
  4. If the new version does not become ready, the Job goes back to the previous version and replaces the broken pod, so PortDock comes back by itself.
  5. The version that starts afterwards records how it went: *Settings → Updates* shows the steps, including the Job's log after a rollback, and the `update.success` or `update.failed` notification is sent.
- **Signatures are checked without Docker.** The image now includes `cosign`, so a PortDock without the Docker socket (in a cluster) verifies new releases too, and the others no longer start a container for it.
- *Settings → Updates* explains what is missing when PortDock cannot update itself, with the command that does it by hand meanwhile.

### Notes

- **Kubernetes installations from before v1.18.0 need one more manual step.** PortDock needs the right to update its own StatefulSet. Give it once by running the installer again, which installs v1.18.0 at the same time:

  ```bash
  curl -fsSL https://github.com/gavrilencu/PortDock/releases/download/v1.18.0/install-kubernetes.sh | sudo bash
  ```

  With `deploy/kubernetes/portdock.yaml`, apply it again instead. Every update after that is one click.
- The right is limited to PortDock's own namespace (Role `portdock-self-update`): its StatefulSet, the controller revisions used to go back, its pods, and Jobs. Nothing in the namespaces of your applications changes.
- Docker installations update exactly as before.
