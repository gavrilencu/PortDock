## HTTPS on Kubernetes, completed: certificates, renewals, redirects and DNS checks

On Kubernetes the certificates themselves were issued (cert-manager and Let's Encrypt), but the Domains tab did not show them, the renew button failed with *read acme.json: this operation is not available on a Kubernetes cluster yet*, HTTP was not redirected to HTTPS, and every domain showed *Wrong IP*.

### Fixes

- **Certificates are checked on Kubernetes.** The Domains tab shows the certificate visitors actually receive: its issuer, its expiry, and *valid* or *expiring*. While there is none yet, it says why, from cert-manager: no issuer set on the cluster, cert-manager missing, or the state of the Let's Encrypt challenge (*wrong status code '404'*, a DNS record that does not point to the server…). The `certificate.expiring` and `certificate.failed` notifications cover these domains too.
- **Renew works on Kubernetes.** The renew button asks cert-manager to issue the certificate again, as `cmctl renew` does, instead of looking for the `acme.json` file of the Docker proxy.
- **HTTP is redirected to HTTPS on Kubernetes.** With Traefik as the ingress controller (k3s, and the Kubernetes installer), the domains of an application with *Redirect HTTP to HTTPS* send plain HTTP requests to HTTPS, permanently. PortDock creates the middleware `pd-https-redirect` in the namespace and refers to it from the application's Ingress. An application that keeps a plain HTTP domain is not redirected, and the Let's Encrypt challenges keep working on HTTP. ingress-nginx redirects HTTPS Ingresses by itself.
- **No more *Wrong IP* for the cluster PortDock runs in.** Its domains are checked against the public address of the machine (Settings → Network), which PortDock now finds by itself when none is set.

### Notes

- **Run the Kubernetes installer once more** to give PortDock the rights these need in the namespaces of your applications (ClusterRole `portdock-ingress`: Traefik middlewares, renewing cert-manager certificates, reading ACME challenges). It installs v1.18.1 at the same time and keeps everything:

  ```bash
  curl -fsSL https://github.com/gavrilencu/PortDock/releases/download/v1.18.1/install-kubernetes.sh | sudo bash
  ```

  With `deploy/kubernetes/portdock.yaml`, apply it again. Without these rights, PortDock says so in the deployment log, and the rest works as before.
- Then redeploy an application, or save its domains, for its Ingress to get the redirect.
